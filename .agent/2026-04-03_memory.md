# Go Runtime & Systems Deep Dive Memory (2026-04-03)

## 1. Go GC & Memory Internals
- **GC Mechanics**: Mastered Tri-color marking, Write Barrier (prevents missing pointers), and Double Buffering (`allocBits` vs `gcmarkBits`).
- **Memory Management**: Understood Arena-based heap (64MB units), Stack Growth (dynamic copying), and the GMP model.
- **Escape Analysis**: How Go decides between Stack (cheap) vs. Heap (expensive).

## 2. Memory Leak & Defensive Engineering
- **Goroutine Leak**: The primary OOM cause. Blocked Gs act as GC Roots, pinning stack-reachable objects.
- **Slice Sub-slicing**: Capturing small parts of large arrays keeps the whole array alive. Use `copy()` or `bytes.Clone()`.
- **Timer Leaks**: Importance of `defer ticker.Stop()`.

## 3. High-Concurrency Architecture
- **Sharding**: Ordered concurrency via `Hash(ID) % N`. Solves lock contention but risks Data Skew.
- **Actor Model (Proto.Actor)**: Bypasses channel overhead using MPSC lock-free queues and batching.
- **Snowflake**: Distributed 64-bit ID generation. No-collision guarantee if Machine ID and Clock remain stable.

## 4. Performance & Tools
- **BigCache**: Zero GC overhead via Pointer-less Map (`map[uint64]uint32`) and Ring Buffer.
- **Profiling**: Use `uber-go/goleak` for tests and `net/http/pprof` for production (Heap/Goroutine analysis).
- **Reflection**: Understand eface structure and why caching schema (offsets/tags) is mandatory for performance.
